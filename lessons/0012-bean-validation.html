第 12 课：参数校验（Bean Validation）

预计用时：25 分钟 | 难度：中级 | 前置知识：第 11 课 全局异常处理

目标：用注解代替手写校验

第 9 课在 Service 里手写了邮箱查重逻辑。但如果用户提交的 name 是空字符串？email 格式不对？age 传了 -1？这些校验如果都手写，Service 会变成一堆 if：

// 手写校验 -- 又臭又长
if (user.getName() == null || user.getName().isEmpty()) {
    throw new IllegalArgumentException("姓名不能为空");
}
if (user.getEmail() == null || !user.getEmail().contains("@")) {
    throw new IllegalArgumentException("邮箱格式不正确");
}
if (user.getAge() != null && user.getAge() < 0) {
    throw new IllegalArgumentException("年龄不能为负数");
}
// ... 还有多少字段要校验？

你在前端一定用过 Element Plus 的 rules 或 VeeValidate -- 在表单上声明校验规则，框架自动执行。Java 也有类似的东西：Bean Validation（JSR 380），用注解声明规则，框架自动校验。

前端（你已熟悉）

// Element Plus 表单校验规则
rules: {
  name: [
    { required: true,
      message: '姓名不能为空' }
  ],
  email: [
    { required: true, message: '邮箱不能为空' },
    { type: 'email', message: '邮箱格式不正确' }
  ]
}

后端（今天学的）

// Bean Validation 注解
public class User {
    @NotBlank(message = "姓名不能为空")
    private String name;

    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;

    @Min(value = 0, message = "年龄不能为负数")
    private Integer age;
}

第一步：添加依赖

在 pom.xml 的 <dependencies> 中添加：

<!-- Bean Validation -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-validation</artifactId>
</dependency>

为什么需要单独引入？

Spring Boot 2.3 起把 validation 从 web starter 中移除了，需要手动添加。底层实现是 Hibernate Validator（和数据库的 Hibernate 没关系，只是同一个团队出品）。

第二步：给 Entity 加校验注解

在 User.java 的字段上加注解：

package com.yourname.demo.entity;

import com.baomidou.mybatisplus.annotation.IdType;
import com.baomidou.mybatisplus.annotation.TableId;
import com.baomidou.mybatisplus.annotation.TableName;
import jakarta.validation.constraints.*;
import lombok.AllArgsConstructor;
import lombok.Data;
import lombok.NoArgsConstructor;

@Data
@TableName("user")
@NoArgsConstructor
@AllArgsConstructor
public class User {

    @TableId(type = IdType.AUTO)
    private Long id;

    @NotBlank(message = "姓名不能为空")
    private String name;

    @Min(value = 0, message = "年龄不能为负数")
    private Integer age;

    @NotBlank(message = "邮箱不能为空")
    @Email(message = "邮箱格式不正确")
    private String email;
}

常用校验注解速查

注解 作用 前端类比
@NotBlank 不能为 null、空字符串、纯空格 { required: true }
@NotEmpty 不能为 null、空字符串（允许纯空格） { required: true }
@NotNull 不能为 null（允许空字符串） -
@Email 必须是合法邮箱格式 { type: 'email' }
@Min(0) 数字最小值 0 { min: 0 }
@Max(150) 数字最大值 150 { max: 150 }
@Size(min=2, max=20) 字符串长度 2-20 { min: 2, max: 20 }
@Pattern(regexp = "^1[3-9]\\d{9}$") 正则匹配（如手机号） { pattern: /^1[3-9]\d{9}$/ }

@NotBlank vs @NotNull 的区别

这是最常见的坑：

  • @NotNull -- null 不行，"" 行
  • @NotEmpty -- null 不行，"" 不行，" " 行
  • @NotBlank -- null 不行，"" 不行，" " 不行（最严格）

字符串字段用 @NotBlank，数字字段用 @NotNull + @Min/@Max。

第三步：Controller 加 @Valid

光在 Entity 上加注解不够 -- 还得告诉 Spring "请校验这个参数"。在 Controller 的 @RequestBody 前加 @Valid：

@PostMapping
public User create(@Valid @RequestBody User user) {
    return userService.createUser(user);
}

@PutMapping("/{id}")
public User update(@PathVariable Long id, @Valid @RequestBody User user) {
    user.setId(id);
    userService.updateById(user);
    return userService.getById(id);
}

就这么一个注解，Spring 在进入方法体之前就会自动校验 user 的每个字段。校验不通过时，直接抛出 MethodArgumentNotValidException，根本不会执行方法体内的代码。

@Valid 是什么？

@Valid 是 JSR 380 标准注解，告诉 Spring："请对这个参数执行 Bean Validation"。就像前端表单提交前调用 formRef.validate() 一样 -- 不过这里是自动的，不需要手动调。

第四步：处理校验异常

校验失败时 Spring 抛出 MethodArgumentNotValidException。如果不处理，又会返回 HTML 错误页。在 第 11 课的 GlobalExceptionHandler 中添加：

// 添加到 GlobalExceptionHandler.java
@ExceptionHandler(MethodArgumentNotValidException.class)
public Map<String, Object> handleValidation(MethodArgumentNotValidException e) {
    // 收集所有字段的校验错误
    String message = e.getBindingResult().getFieldErrors().stream()
            .map(err -> err.getField() + ": " + err.getDefaultMessage())
            .collect(Collectors.joining("; "));
    return Map.of("code", 400, "message", message);
}

需要补充 import：

import org.springframework.web.bind.MethodArgumentNotValidException;
import java.util.stream.Collectors;

这段代码做了什么：

  1. e.getBindingResult().getFieldErrors() -- 获取所有校验失败的字段
  2. .map(err -> err.getField() + ": " + err.getDefaultMessage()) -- 拼成 "email: 邮箱格式不正确"
  3. .collect(Collectors.joining("; ")) -- 多个错误用分号拼接

完全兼容

Bean Validation（JSR 380）和 Hibernate Validator 支持 JDK 8。Spring Boot 2.x 下只需把 import 从 jakarta.validation 换成 javax.validation。Stream API 是 JDK 8 原生特性。

测试空姓名

POST http://localhost:8080/api/users
Content-Type: application/json

{"email":"test@dev.com"}

  "code": 400,

}

测试非法邮箱

POST http://localhost:8080/api/users
Content-Type: application/json

{"name":"Test","email":"not-an-email"}

响应：

{
  "code": 400,
  "message": "email: 邮箱格式不正确"
}

测试多字段同时出错

POST http://localhost:8080/api/users
Content-Type: application/json

{"age":-5,"email":"bad"}

响应（所有错误一次性返回）：

{
  "code": 400,
  "message": "name: 姓名不能为空; age: 年龄不能为负数; email: 邮箱格式不正确"
}

前端可以按 ; 分割，逐条展示给用户 -- 和 Element Plus 表单校验一次性标红所有字段是一样的体验。

小测验

@Valid 注解应该放在哪里？

  • 放在 Service 实现类上面
  • 放在 Controller 方法参数前
  • 放在 Entity 类的注解里
  • 放在 pom.xml 的依赖中

小测验

@NotBlank 和 @NotNull 的核心区别是什么？

  • 两者功能完全相同无区别
  • NotBlank 还拒绝空白字符串
  • NotNull 还校验数字范围
  • NotBlank 只能用于数字类型

小测验

Bean Validation 校验失败时抛出什么异常？

  • NullPointerException 异常
  • IllegalArgumentException 异常
  • MethodArgumentNotValidException
  • ConstraintViolationException
