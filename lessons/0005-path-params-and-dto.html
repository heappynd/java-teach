目标：写一个用户管理 API

上一课你学会了查询参数（?name=Vue）和请求体（@RequestBody）。这节课我们要写更贴近真实的 API：

  1. 路径参数：/users/42 获取 ID 为 42 的用户
  2. DTO：用结构化对象返回数据，而不是裸 Map
  3. 内存 CRUD：用 List 存数据，实现增删改查

完成后你就有了一个完整的用户管理 API -- 离接数据库只差一步。

路径参数 @PathVariable

前端路由你一定见过 /users/:id，Spring Boot 里也一样：

Vue Router

// 路由定义
{ path: '/users/:id', component: UserDetail }

// 获取参数
const id = route.params.id  // "42"

Spring Boot

// 路由定义
@GetMapping("/users/{id}")

// 获取参数
public String getUser(
    @PathVariable Long id) {  // 42
}
概念 查询参数 @RequestParam 路径参数 @PathVariable
URL 格式 /users?name=Vue /users/42
前端类比 req.query.name route.params.id
什么时候用 过滤、搜索条件 定位某个具体资源

DTO：用结构化对象代替 Map

上一课我们用 Map.of() 返回数据，能跑但有问题：

  • 没有类型提示，IDE 不知道有哪些字段
  • 字段名打错了不会报错
  • 没法做数据验证

就像前端用 any 类型 vs 用 interface 的区别。Java 中用 Record 定义 DTO：

TypeScript（你熟悉的）

// 定义接口
interface User {
  id: number
  name: string
  email: string
}

// 使用
const user: User = {
  id: 1,
  name: "Vue",
  email: "vue@dev.com"
}

Java Record（今天学的）

// 定义 Record
public record User(
    Long id,
    String name,
    String email
) {}

// 使用
User user = new User(
    1L,
    "Vue",
    "vue@dev.com"
);

Record 是 Java 14+ 引入的语法，专门用来定义数据类。它自动生成构造器、getter、equals、toString。你只需声明字段，其余的 Java 帮你搞定。对前端开发者来说，它就是 TypeScript 的 interface + 构造函数的合体。

不支持

record 是 JDK 14+（预览）/ JDK 16+（正式）语法，JDK 8 中不可用。这是本课最重要的 JDK 8 兼容性问题。

JDK 8 替代写法 -- 普通类 + 手动构造器/getter：

public class User {
    private Long id;
    private String name;
    private String email;

    public User(Long id, String name, String email) {
        this.id = id;
        this.name = name;
        this.email = email;
    }

    public Long getId() { return id; }
    public String getName() { return name; }
    public String getEmail() { return email; }
}

注意：JDK 8 中 getter 是 getId() 而非 Record 的 id()。JSON 序列化结果相同。

国内 JDK 8 项目中常用 Lombok 的 @Data + @AllArgsConstructor 注解自动生成上述代码，体验接近 Record。

Record 关键差异

特性 TypeScript interface Java Record
定义字段 id: number Long id（类型在前）
创建实例 { id: 1, name: "Vue" } new User(1L, "Vue")
读取字段 user.name user.name()（带括号！）
数字类型 number（统一） Long（整数）/ Double（小数）
整数字面量 1 1L（L 表示 Long 类型）

注意：getter 带括号

Java Record 的字段访问是方法调用：user.name() 不是 user.name。这是因为 Java 没有属性访问器语法，getter 方法名就是字段名。按 Alt + Enter 会自动帮你加括号。

实战：用户管理 API

创建 User Record

在 entity 包下（com.yourname.demo.entity）新建 User.java：

package com.yourname.demo.entity;

public record User(
    Long id,
    String name,
    String email
) {}

就这么简单，一个 User DTO 定义完了。等同于 TypeScript 的：

interface User {
  id: number
  name: string
  email: string
}

创建 UserController

在 controller 包下新建 UserController.java，先用内存 List 存数据：

package com.yourname.demo.controller;

import com.yourname.demo.entity.User;
import org.springframework.web.bind.annotation.*;

import java.util.ArrayList;
import java.util.List;

@RestController
@RequestMapping("/users")
public class UserController {

    // 内存存储，暂代数据库（下节课换真数据库）
    private List<User> users = new ArrayList<>(List.of(
        new User(1L, "Vue", "vue@dev.com"),
        new User(2L, "React", "react@dev.com"),
        new User(3L, "Angular", "angular@dev.com")
    ));

    // GET /users - 获取所有用户
    @GetMapping
    public List<User> getAll() {
        return users;
    }

    // GET /users/1 - 获取单个用户
    @GetMapping("/{id}")
    public User getById(@PathVariable Long id) {
        return users.stream()
            .filter(u -> u.id().equals(id))
            .findFirst()
            .orElse(null);
    }

    // POST /users - 创建用户
    @PostMapping
    public User create(@RequestBody User user) {
        users.add(user);
        return user;
    }

    // DELETE /users/1 - 删除用户
    @DeleteMapping("/{id}")
    public String delete(@PathVariable Long id) {
        users.removeIf(u -> u.id().equals(id));
        return "Deleted user " + id;
    }
}

理解新概念

类级别路由 @RequestMapping("/users")

给整个 Controller 加路径前缀。方法上的 @GetMapping("/{id}") 实际路径是 /users/{id}。相当于 Vue Router 的嵌套路由。

List<User>

相当于 TypeScript 的 User[]。ArrayList 是可变 List（类似 JS 的普通数组），List.of(...) 创建不可变 List。

不支持

List.of() 是 JDK 9+ 引入的工厂方法，JDK 8 中不可用。JDK 8 替代写法：

// JDK 8 写法
import java.util.Arrays;

private List<User> users = new ArrayList<>(Arrays.asList(
    new User(1L, "Vue", "vue@dev.com"),
    new User(2L, "React", "react@dev.com"),
    new User(3L, "Angular", "angular@dev.com")
));

Arrays.asList() 返回固定大小列表，套一层 new ArrayList<>() 使其可变。

users.stream().filter(...).findFirst().orElse(null)

这是 Java 的流式 API，相当于 JS 的：

// JS 等价写法
users.find(u => u.id === id) || null
Java Stream JS Array
users.stream() users（数组本身就是可迭代的）
.filter(u -> u.id().equals(id)) .filter(u => u.id === id)
.findFirst() （filter 返回的数组取第一个）
.orElse(null) || null
u -> u.id().equals(id) u => u.id === id

为什么用 equals() 不用 ==？

Java 中 == 比较的是引用（内存地址），equals() 比较的是值。对于 Long、String 等对象类型，必须用 equals()。这和 JS 不同 -- JS 的 === 对基本类型比较值。Java 中基本类型（int, long）用 ==，包装类型（Integer, Long）用 equals()。

实战

动手挑战：天气查询 API

你学会了 @PathVariable 和 DTO。现在创建一个不依赖数据库的天气查询 API，练习路径参数和结构化返回。

需求

  • 创建 Weather DTO 类（record 或 Lombok @Data），字段：String city, int temperature, String condition
  • 在 controller 包下新建 WeatherController.java
  • GET /weather/{city} -> 返回该城市的 Weather DTO
  • 内存中存 3 个城市数据（用 Map 或 List），如：beijing/25/晴, shanghai/28/多云, guangzhou/30/雷阵雨
  • 城市不存在时返回 null（暂不处理异常，下几课再学）

需要创建的文件

  1. entity/Weather.java - DTO 类（record 或 Lombok @Data）
  2. controller/WeatherController.java - 天气控制器

验收清单（我会逐项检查）

  • Weather 类定义了 city、temperature、condition 三个字段
  • Controller 用 @GetMapping("/weather/{city}")
  • 用 @PathVariable String city 接收路径参数
  • 内存中至少存了 3 个城市
  • 访问 /weather/beijing 返回 JSON 格式的天气数据
  • 访问不存在的城市返回 null
  • 代码能编译通过
卡住了？点开看提示（建议先自己想 5 分钟）
提示 1：DTO 用 record 还是普通类？

都可以。record 更简洁（JDK 14+）：public record Weather(String city, int temperature, String condition) {}。JDK 8 用 Lombok @Data + @AllArgsConstructor。

提示 2：内存数据怎么存？

用 Map<String, Weather>。Map.of("beijing", new Weather("beijing", 25, "晴"), ...)（JDK 9+）或 HashMap + put（JDK 8）。

提示 3：找不到城市怎么办？

map.get(city) 找不到自然返回 null。Spring 会把 null 序列化成 JSON 的 null。
