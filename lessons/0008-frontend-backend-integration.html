第一步：理解跨域（CORS）

开发时，Vue3 跑在 http://localhost:5173，Spring Boot 跑在 http://localhost:8080。端口不同 = 源不同，浏览器会阻止前端 JS 读取后端的响应 -- 这就是 CORS（Cross-Origin Resource Sharing）问题。

浏览器的同源策略

浏览器规定：JS 发出的请求，如果目标与当前页面协议、域名、端口任一不同，就是"跨域"。浏览器会先检查后端是否允许跨域 -- 不允许就拦截响应。

注意：请求发出去了，后端也处理了，只是浏览器不让 JS 读结果。这不是 bug，是浏览器的安全机制。

前端地址 后端地址 是否跨域 原因
localhost:5173 localhost:8080 是 端口不同
localhost:5173 localhost:5173/api 否 同源（Vite 代理）
example.com api.example.com 是 域名不同

有两种解决方案：

方案 适用场景 原理
Vite 代理 开发环境 Vite dev server 转发请求，浏览器认为是同源
Spring Boot CORS 配置 生产环境 / 不便代理时 后端响应头声明允许哪些前端源访问

实际开发中两个都要配：开发用代理方便，生产用 CORS 配置。下面逐一操作。

第二步：开发环境 -- Vite 代理（推荐）

这是你最熟悉的方案。Vite dev server 充当中间人，把 /api/* 的请求转发到 Spring Boot，浏览器看到的全是同源请求，没有 CORS 问题。

// vite.config.js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'

export default defineConfig({
  plugins: [vue()],
  server: {
    proxy: {
      '/api': {
        target: 'http://localhost:8080',
        changeOrigin: true,
        rewrite: (path) => path.replace(/^\/api/, '')
      }
    }
  }
})
配置项 说明
'/api' 匹配所有以 /api 开头的请求
target 转发目标 -- Spring Boot 地址
changeOrigin: true 修改请求头中的 Host 为 target 地址
rewrite 去掉 /api 前缀：/api/users -> /users

这样，前端 axios 请求 /api/users，Vite 自动转发到 http://localhost:8080/users，浏览器看到的是 localhost:5173/api/users -- 同源，无 CORS。

浏览器 -> localhost:5173/api/users
               │ Vite 代理转发
               ▼
          localhost:8080/users  (Spring Boot)

第三步：生产环境 -- Spring Boot CORS 配置

生产环境中前端通常打包成静态文件，由 Nginx 托管或嵌入 Spring Boot。但如果前后端分别部署在不同域名/端口，就需要后端配置 CORS。

在 Spring Boot 项目中新建 CorsConfig.java（与 DemoApplication.java 同级）：

package com.yourname.demo;

import org.springframework.context.annotation.Configuration;
import org.springframework.web.servlet.config.annotation.CorsRegistry;
import org.springframework.web.servlet.config.annotation.WebMvcConfigurer;

@Configuration
public class CorsConfig implements WebMvcConfigurer {

    @Override
    public void addCorsMappings(CorsRegistry registry) {
        registry.addMapping("/**")                    // 对所有路径生效
                .allowedOrigins("http://localhost:5173")  // 允许的前端源
                .allowedMethods("GET", "POST", "PUT", "DELETE", "OPTIONS")
                .allowedHeaders("*")                   // 允许所有请求头
                .allowCredentials(true);               // 允许携带 Cookie
    }
}
配置项 说明 前端类比
addMapping("/**") 对所有 API 路径生效 -
allowedOrigins 允许哪些前端地址访问 白名单
allowedMethods 允许的 HTTP 方法 -
allowCredentials(true) 允许携带 Cookie（登录场景需要） axios.defaults.withCredentials = true

CORS 原理

配置后，Spring Boot 会在响应头中加上 Access-Control-Allow-Origin: http://localhost:5173。浏览器看到这个头，就知道后端允许该前端访问，于是放行 JS 读取响应。

对于 PUT、DELETE 等非简单请求，浏览器会先发一个 OPTIONS 预检请求，Spring Boot 自动处理并返回允许的方法。你不需要手写 OPTIONS 接口。

开发时也要配 CORS 吗？

如果用了 Vite 代理，开发时不需要配 CORS -- 代理已经解决了。但建议两个都配上，这样切换环境时不会出问题。生产环境如果用 Nginx 反向代理统一入口，也可以不配 CORS -- 和 Vite 代理同理。

第五步：API 调用层

新建 src/api/user.js：

import axios from 'axios'

const api = axios.create({
  baseURL: '/api',   // 走 Vite 代理
  timeout: 5000
})

export default {
  getList(params) {
    return api.get('/users', { params })
  },
  getById(id) {
    return api.get(`/users/${id}`)
  },
  create(data) {
    return api.post('/users', data)
  },
  update(id, data) {
    return api.put(`/users/${id}`, data)
  },
  delete(id) {
    return api.delete(`/users/${id}`)
  }
}

baseURL: '/api' 的作用

所有请求自动加上 /api 前缀：api.get('/users') 实际请求 /api/users -> Vite 代理转发到 http://localhost:8080/users。生产环境把 baseURL 改成实际后端地址即可。

第六步：用户管理页面

替换 src/App.vue，一个完整的增删改查页面：

<script setup>
import { ref, onMounted } from 'vue'
import userApi from './api/user.js'

const users = ref([])
const total = ref(0)
const currentPage = ref(1)
const pageSize = ref(5)
const searchName = ref('')

const dialogVisible = ref(false)
const editing = ref(false)
const form = ref({ id: null, name: '', email: '' })

async function loadData() {
  const res = await userApi.getList({
    page: currentPage.value,
    size: pageSize.value,
    name: searchName.value || undefined
  })
  users.value = res.data.records
  total.value = res.data.total
}

function handleSearch() {
  currentPage.value = 1
  loadData()
}

function openCreate() {
  editing.value = false
  form.value = { id: null, name: '', email: '' }
  dialogVisible.value = true
}

function openEdit(user) {
  editing.value = true
  form.value = { ...user }
  dialogVisible.value = true
}

async function save() {
  if (editing.value) {
    await userApi.update(form.value.id, form.value)
  } else {
    await userApi.create(form.value)
  }
  dialogVisible.value = false
  loadData()
}

async function remove(id) {
  if (!confirm('确定删除？')) return
  await userApi.delete(id)
  loadData()
}

onMounted(loadData)
</script>

<template>
  <div style="max-width: 700px; margin: 2rem auto;">
    <h1>用户管理</h1>

    <!-- 搜索栏 -->
    <div style="display: flex; gap: 0.5rem; margin-bottom: 1rem;">
      <input v-model="searchName" placeholder="搜索姓名"
             @keyup.enter="handleSearch" />
      <button @click="handleSearch">搜索</button>
      <button @click="openCreate">新增</button>
    </div>

    <!-- 数据表格 -->
    <table border="1" style="width: 100%; border-collapse: collapse;">
      <thead>
        <tr>
          <th>ID</th>
          <th>姓名</th>
          <th>邮箱</th>
          <th>操作</th>
        </tr>
      </thead>
      <tbody>
        <tr v-for="user in users" :key="user.id">
          <td>{{ user.id }}</td>
          <td>{{ user.name }}</td>
          <td>{{ user.email }}</td>
          <td>
            <button @click="openEdit(user)">编辑</button>
            <button @click="remove(user.id)">删除</button>
          </td>
        </tr>
      </tbody>
    </table>

    <!-- 分页 -->
    <div style="margin-top: 1rem; display: flex; gap: 1rem; align-items: center;">
      <button :disabled="currentPage <= 1"
              @click="currentPage--; loadData()">上一页</button>
      <span>第 {{ currentPage }} 页 / 共
            {{ Math.ceil(total / pageSize) }} 页
            ({{ total }} 条)</span>
      <button :disabled="currentPage >= Math.ceil(total / pageSize)"
              @click="currentPage++; loadData()">下一页</button>
    </div>

    <!-- 新增/编辑弹窗 -->
    <div v-if="dialogVisible"
         style="margin-top: 1rem; padding: 1rem; border: 1px solid #ccc;">
      <h3>{{ editing ? '编辑用户' : '新增用户' }}</h3>
      <input v-model="form.name" placeholder="姓名" />
      <input v-model="form.email" placeholder="邮箱" />
      <button @click="save">保存</button>
      <button @click="dialogVisible = false">取消</button>
    </div>
  </div>
</template>

小测验

浏览器阻止跨域请求时，请求是否到达了后端？

  • 没有到达后端被浏览器拦截
  • 到达后端了但浏览器不给响应
  • 后端收到了但拒绝返回数据
  • 浏览器和后端都没有处理

小测验

Vite 代理为什么能解决跨域问题？

  • 请求发给同源的 Vite 再转发
  • Vite 修改了浏览器的安全策略
  • Vite 给请求加上了 CORS 头
  • Vite 和后端共享同一个端口

小测验

Spring Boot 的 CORS 配置中 allowedOrigins 的作用是什么？

  • 限制后端只能访问的前端地址
  • 声明允许访问后端的前端地址
  • 设置前端静态资源的存放路径
  • 配置数据库连接的来源地址
