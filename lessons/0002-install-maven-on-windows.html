第 2 课：在 Windows 上安装 Maven

预计用时：15 分钟 | 难度：入门 | 前置知识：第 1 课 JDK 安装

Maven 是什么？

你已经装好了 JDK，现在需要 Maven -- Java 世界的包管理器和构建工具。

前端（你已熟悉）

npm 负责下载依赖、运行脚本、打包项目

package.json 声明依赖列表

node_modules/ 存放下载的依赖

后端（今天学的）

Maven 负责下载依赖、编译代码、打包项目

pom.xml 声明依赖列表

~/.m2/repository 存放下载的依赖

一个关键区别：npm 的 node_modules 是每个项目单独存一份依赖，而 Maven 的 ~/.m2/repository 是全局共享的 -- 多个项目用同一个依赖只需要下载一次。这更节省磁盘空间。

Maven vs Gradle

Java 世界有两个主流构建工具，就像前端有 npm 和 pnpm：

工具 前端类比 特点
Maven npm 最主流，配置用 XML，约定优于配置，文档丰富
Gradle pnpm / Vite 更快更灵活，配置用 Groovy/Kotlin，学习曲线陡

本课程使用 Maven，因为它是 Spring Boot 项目最常见的构建工具，社区资源最多。

开始安装

下载 Maven

打开 Maven 官方下载页，找到下载列表中的：

  • Binary zip archive - 文件名类似 apache-maven-3.9.x-bin.zip

点击下载，不需要下 source 版本。

小贴士

选 bin（二进制版）不要选 src（源码版）。bin 是编译好的可直接使用版本，就像你用 npm 装包不会去下源码自己编译。

解压到固定目录

将下载的 zip 文件解压到一个固定目录，推荐：

# 推荐解压到这个路径：
C:\dev\apache-maven-3.9.x

解压后目录结构应该是这样的：

C:\dev\apache-maven-3.9.x\
├── bin\          <-- Maven 可执行文件（mvn.cmd 在这里）
├── boot\
├── conf\         <-- 配置文件（settings.xml 在这里）
├── lib\
└── LICENSE

注意

路径中不要有中文和空格。C:\Program Files\ 可以但不推荐（有空格）。用 C:\dev\ 这样的简单路径最省心。

配置环境变量

和装 JDK 时一样，需要把 Maven 加到系统环境变量。按 Win + S 搜索"环境变量"，打开"编辑系统环境变量"：

  1. 点击"环境变量"按钮
  2. 在"系统变量"中点"新建"：
    • 变量名：MAVEN_HOME
    • 变量值：C:\dev\apache-maven-3.9.x（你解压的路径，不含 bin）
  3. 找到"系统变量"中的 Path，点"编辑"
  4. 点"新建"，添加：%MAVEN_HOME%\bin
  5. 一路"确定"保存

为什么叫 MAVEN_HOME？

和 JAVA_HOME 一样的套路：给工具一个固定的变量名指向安装目录。Maven 的某些插件需要通过 MAVEN_HOME 找到 Maven 本体。

配置国内镜像（重要！）

Maven 默认从国外的 Maven Central 下载依赖，在国内速度很慢。就像 npm 默认从国外 registry 下载很慢一样。我们需要配置国内镜像。

找到 Maven 配置文件：C:\dev\apache-maven-3.9.x\conf\settings.xml

用编辑器打开它，找到 <mirrors> 标签，在里面添加阿里云镜像：

<mirrors>
  <mirror>
    <id>aliyunmaven</id>
    <mirrorOf>*</mirrorOf>
    <name>阿里云公共仓库</name>
    <url>https://maven.aliyun.com/repository/public</url>
  </mirror>
</mirrors>

前端类比

这就像运行 npm config set registry https://registry.npmmirror.com 切换淘宝镜像。不配镜像的话，下载依赖可能要等几分钟甚至超时。

验证安装

关闭所有已打开的终端窗口，打开一个新的 PowerShell，输入：

PS C:\> mvn -version
Apache Maven 3.9.x (...) Maven home: C:\dev\apache-maven-3.9.x Java version: 17.0.x, vendor: Eclipse Adoptium, runtime: C:\Program Files\Eclipse Adoptium\jdk-17.x.x-hotspot Default locale: zh_CN, platform encoding: UTF-8 OS name: "windows 11", version: "10.0", arch: "amd64", family: "windows"

如果看到 Maven 版本号，并且 Java version 显示 17，说明 Maven 和 JDK 都配置正确！

排错

如果输出中 Java version 不是 17 或报错"JAVA_HOME not found"，回头检查第一课的 JAVA_HOME 是否设置正确。Maven 依赖 JAVA_HOME 找到 JDK。

Maven 速查：常用命令

先混个眼熟，后面课程会在实际项目中用到这些命令：

Maven 命令 等价的前端命令 作用
mvn clean rm -rf dist 清理编译输出
mvn compile tsc 编译源代码
mvn test npm test 运行单元测试
mvn package npm run build 编译 + 测试 + 打包成 .jar
mvn install npm link 打包并安装到本地仓库
mvn spring-boot:run npm run dev 启动 Spring Boot 应用（后面课会用）

理解 Maven 的工作流程

你在 pom.xml 中声明依赖
        │
        ▼
mvn compile 执行
        │
        ▼
Maven 检查 ~/.m2/repository 是否有该依赖
        │
    ┌───┴───┐
    │       │
  有依赖   没依赖
    │       │
    │       ▼
    │    从镜像仓库下载
    │    (阿里云/Maven Central)
    │       │
    │       ▼
    │    存入 ~/.m2/repository
    │       │
    └───┬───┘
        │
        ▼
  编译你的 Java 代码

这和 npm 的工作流程几乎一样，只是依赖存储位置从项目内的 node_modules 变成了全局的 ~/.m2/repository。

小测验

Maven 的依赖存储方式与 npm 有什么关键区别？

  • Maven 把依赖存在项目目录内
  • Maven 把依赖全局共享存在统一目录
  • Maven 不需要下载依赖
  • Maven 依赖存在云端不下载

小测验

为什么 Maven 需要通过 JAVA_HOME 找到 JDK？

  • Maven 用 Java 写的需 JDK 运行
  • Maven 需调用 javac 来编译代码
  • Maven 要用 JDK 来下载依赖包
  • Maven 把 JDK 作为依赖来管理
