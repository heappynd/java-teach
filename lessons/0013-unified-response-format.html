第 13 课：统一响应格式

预计用时：25 分钟 | 难度：中级 | 前置知识：第 12 课 参数校验

目标：所有 API 返回统一结构

到目前为止，你的 API 返回格式五花八门：

接口 当前返回 问题
GET /users {"records":[...],"total":16,...} 直接返回 Page 对象，前端要猜结构
GET /users/1 {"id":1,"name":"Vue",...} 直接返回 User 对象
DELETE /users/1 "Deleted user 1" 返回纯字符串，和其他接口格式完全不同
出错时 {"code":400,"message":"邮箱已被注册"} 错误有格式，成功却没有

前端每次都要判断"这个接口返回的是什么结构"，很烦。统一成一个格式：

// 成功
{ "code": 200, "message": "success", "data": { ... } }

// 失败
{ "code": 400, "message": "邮箱已被注册", "data": null }

前端（你已熟悉）

Axios 响应拦截器：

axios.interceptors.response.use(
  res => {
    if (res.data.code === 200) {
      return res.data.data  // 直接取 data
    }
    ElMessage.error(res.data.message)
    return Promise.reject()
  }
)

前端只需写一次拦截器，所有接口统一处理

后端（今天学的）

Result 包装类：

@GetMapping("/{id}")
public Result<User> getById(
    @PathVariable Long id) {
  return Result.success(
    userService.getById(id));
}

所有接口返回 Result，格式统一

第一步：创建 Result 包装类

在 common 包下新建 Result.java：

package com.yourname.demo.common;

import lombok.Data;

@Data
public class Result<T> {
    private int code;
    private String message;
    private T data;

    // 成功 -- 带数据
    public static <T> Result<T> success(T data) {
        Result<T> r = new Result<>();
        r.setCode(200);
        r.setMessage("success");
        r.setData(data);
        return r;
    }

    // 成功 -- 不带数据（用于 DELETE 等无返回值操作）
    public static <T> Result<T> success() {
        return success(null);
    }

    // 失败
    public static <T> Result<T> error(int code, String message) {
        Result<T> r = new Result<>();
        r.setCode(code);
        r.setMessage(message);
        r.setData(null);
        return r;
    }
}

逐行解读：

部分 说明 前端类比
Result<T> 泛型类。T 是 data 的类型 -- Result<User> 的 data 就是 User TypeScript 的 interface Result<T>
static <T> Result<T> success(T data) 静态工厂方法。调用 Result.success(user) 就能创建成功响应 类似 Object.create() 工厂模式
@Data Lombok 自动生成 getter/setter，Jackson 才能序列化成 JSON -

为什么用静态工厂方法？

如果用 new Result<>() 再逐个 setter，每个接口要写三行。用 Result.success(user) 一行搞定。这和你前端封装 createResponse(data) 是同一个思路。

第二步：Controller 返回 Result

把 UserController 所有方法的返回类型包上 Result：

package com.yourname.demo.controller;

import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import com.yourname.demo.common.Result;
import com.yourname.demo.entity.User;
import com.yourname.demo.service.UserService;
import jakarta.validation.Valid;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/users")
public class UserController {

    private final UserService userService;

    public UserController(UserService userService) {
        this.userService = userService;
    }

    @GetMapping
    public Result<Page<User>> getList(
            @RequestParam(defaultValue = "1") long page,
            @RequestParam(defaultValue = "10") long size,
            @RequestParam(required = false) String name,
            @RequestParam(required = false) String email) {
        return Result.success(userService.pageList(page, size, name, email));
    }

    @GetMapping("/{id}")
    public Result<User> getById(@PathVariable Long id) {
        return Result.success(userService.getById(id));
    }

    @PostMapping
    public Result<User> create(@Valid @RequestBody User user) {
        return Result.success(userService.createUser(user));
    }

    @PutMapping("/{id}")
    public Result<User> update(@PathVariable Long id, @Valid @RequestBody User user) {
        user.setId(id);
        userService.updateById(user);
        return Result.success(userService.getById(id));
    }

    @DeleteMapping("/{id}")
    public Result<?> delete(@PathVariable Long id) {
        userService.removeById(id);
        return Result.success();
    }
}

每个方法只有两处变化：

  • 返回类型从 User 变成 Result<User>（包一层）
  • 返回值从 userService.getById(id) 变成 Result.success(userService.getById(id))（套一层）

delete 方法为什么用 Result<?>？

Result.success() 不带数据时返回 Result<Object>（data 为 null）。用 Result<?> 通配符更准确 -- "返回某种 Result，但不关心 data 的类型"。

第三步：异常处理也用 Result

把 第 11 课和第 12 课的 GlobalExceptionHandler 也改成返回 Result，保持格式统一：

package com.yourname.demo.common;

import org.springframework.web.bind.MethodArgumentNotValidException;
import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import java.util.stream.Collectors;

@RestControllerAdvice
public class GlobalExceptionHandler {

    @ExceptionHandler(IllegalArgumentException.class)
    public Result<?> handleIllegalArgument(IllegalArgumentException e) {
        return Result.error(400, e.getMessage());
    }

    @ExceptionHandler(MethodArgumentNotValidException.class)
    public Result<?> handleValidation(MethodArgumentNotValidException e) {
        String message = e.getBindingResult().getFieldErrors().stream()
                .map(err -> err.getField() + ": " + err.getDefaultMessage())
                .collect(Collectors.joining("; "));
        return Result.error(400, message);
    }

    @ExceptionHandler(Exception.class)
    public Result<?> handleException(Exception e) {
        return Result.error(500, "服务器内部错误");
    }
}

从 Map.of(...) 改成了 Result.error(...)，逻辑完全一样，只是返回格式更统一了。

前端对接：Axios 拦截器

后端统一格式后，前端只需要写一次拦截器，所有接口的处理逻辑就统一了：

// axios 响应拦截器 -- 写一次，全局生效
axios.interceptors.response.use(
  res => {
    const result = res.data  // { code, message, data }
    if (result.code === 200) {
      return result.data      // 成功：直接取 data
    }
    // 失败：弹出错误提示
    ElMessage.error(result.message)
    return Promise.reject(result)
  },
  err => {
    ElMessage.error('网络错误')
    return Promise.reject(err)
  }
)

// 业务代码变得极简 -- 不用判断 code，直接用 data
const users = await axios.get('/api/users')  // 直接拿到 Page<User>
const user = await axios.get('/api/users/1')  // 直接拿到 User

关于 Swagger / OpenAPI

统一响应格式后，可以考虑集成 SpringDoc OpenAPI（Swagger 3）自动生成 API 文档。在 pom.xml 加 springdoc-openapi-starter-webmvc-ui 依赖后，访问 http://localhost:8080/api/swagger-ui.html 就能看到所有接口的在线文档和调试页面。这不在本课范围内，但强烈推荐了解。

完全兼容

Result 是普通 Java 泛型类，JDK 5+ 就支持。Lombok 的 @Data 兼容 JDK 8。Stream API 是 JDK 8 原生特性。无兼容性问题。

小测验

统一响应格式 Result<T> 中泛型 T 代表什么？

  • 代表 HTTP 状态码类型
  • 代表 data 字段的数据类型
  • 代表错误消息的字符串类型
  • 代表请求参数的映射类型

小测验

为什么错误响应也用 Result 格式包装？

  • 为了增加响应的数据量大小
  • 为了让前端统一一套逻辑处理
  • 为了提高服务器的响应速度
  • 为了兼容旧版本的浏览器

小测验

前端如何从 Result 格式中取出实际数据？

  • 从 response.code 字段中取
  • 从 response.data 字段中取
  • 从 response.message 字段中取
  • 从 response.headers 中取
