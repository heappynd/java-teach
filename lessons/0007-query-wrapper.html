目标：让 API 支持搜索、更新和分页

上一课的 API 能增删查，但还缺三样东西：

  • 更新（PUT）-- CRUD 还差一个 U
  • 条件搜索 -- 用户输入"Vu"能搜到 Vue

这节课一次性补齐。你将学会 LambdaQueryWrapper（条件构造器）和 分页插件，这两个是实际开发中天天用的核心技能。

前端（你已熟悉）

axios.get('/users', { params: { page: 1, size: 10, name: 'Vu' } })

后端（今天学的）

第一步：补全 CRUD -- 添加更新接口

上一课实现了 GET、POST、DELETE，还差 PUT（更新）。在 UserController.java 中添加：

@PutMapping("/{id}")
public User update(@PathVariable Long id, @RequestBody User user) {
    user.setId(id);
    userMapper.updateById(user);
    return userMapper.selectById(id);
}
方法 Prisma 类比 生成的 SQL
updateById(user) prisma.user.update() UPDATE users SET name=?, email=? WHERE id=?

null 字段自动跳过

updateById 默认只更新非 null 字段。如果请求体只有 {"name":"NewName"}，email 不会被覆盖为 null -- 这叫"选择性更新"，相当于 Prisma 的 update({ data: { name } })，不传的字段不动。

测试更新接口：

PUT http://localhost:8080/users/1
Content-Type: application/json

{"name":"Vue 4","email":"vue4@dev.com"}

响应：

{"id":1,"name":"Vue 4","email":"vue4@dev.com"}

现在 CRUD 完整了！

第二步：添加分页插件依赖

MyBatis Plus 从 3.5.9 起，分页插件 PaginationInnerInterceptor 被拆分为独立依赖。需要额外引入 mybatis-plus-jsqlparser。

在 pom.xml 中添加 BOM（统一版本管理）和分页依赖：

<!-- 1. 在 <dependencies> 之前添加 BOM -->
<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>com.baomidou</groupId>
            <artifactId>mybatis-plus-bom</artifactId>
            <version>3.5.17</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

<!-- 2. 在 <dependencies> 中添加分页插件 -->
<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-jsqlparser</artifactId>
</dependency>

BOM 是什么？

BOM（Bill of Materials）是 Maven 的版本管理清单。引入 BOM 后，所有 MyBatis Plus 相关依赖的版本由 BOM 统一管理，不需要手动写 <version>。相当于前端 package-lock.json 锁定版本的作用。你之前在 lesson 6 添加的 mybatis-plus-spring-boot4-starter 可以删掉 <version> 标签，由 BOM 接管。

Spring Boot 2.x / JDK 8

JDK 8 需要使用 mybatis-plus-jsqlparser-4.9（因为 jsqlparser 5.0+ 要求 JDK 11+）：

<dependency>
    <groupId>com.baomidou</groupId>
    <artifactId>mybatis-plus-jsqlparser-4.9</artifactId>
</dependency>

BOM 版本同样使用 3.5.17，BOM 会自动选择与 JDK 8 兼容的版本。

第三步：配置分页拦截器

新建配置类 MybatisPlusConfig.java（与 DemoApplication.java 同级目录）：

package com.yourname.demo;

import com.baomidou.mybatisplus.annotation.DbType;
import com.baomidou.mybatisplus.extension.plugins.MybatisPlusInterceptor;
import com.baomidou.mybatisplus.extension.plugins.inner.PaginationInnerInterceptor;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;

@Configuration
public class MybatisPlusConfig {

    @Bean
    public MybatisPlusInterceptor mybatisPlusInterceptor() {
        MybatisPlusInterceptor interceptor = new MybatisPlusInterceptor();
        interceptor.addInnerInterceptor(
            new PaginationInnerInterceptor(DbType.POSTGRE_SQL)
        );
        return interceptor;
    }
}
组成部分 说明
@Configuration 标记为配置类，Spring 启动时自动加载
@Bean 将返回值注册为 Spring Bean，相当于告诉框架"这里有一个你需要管理的对象"
MybatisPlusInterceptor MyBatis Plus 拦截器容器，可以挂载多个内部拦截器
PaginationInnerInterceptor 分页拦截器，自动给 SQL 拼接 LIMIT 和 OFFSET
DbType.POSTGRE_SQL 告诉拦截器用 PostgreSQL 方言生成分页 SQL

拦截器做了什么？

当你调用 selectPage() 时，拦截器会做两件事：
1. 执行 SELECT COUNT(*) 获取总记录数
2. 给原 SQL 拼接 LIMIT 10 OFFSET 0 只取当前页数据
这一切都是自动的 -- 你只需要传 Page 对象。

第四步：LambdaQueryWrapper 条件构造器

上一课的 selectList(null) 查全部。要加 WHERE 条件，需要传入 QueryWrapper。MyBatis Plus 提供两种：

QueryWrapper（字符串字段名）

QueryWrapper<User> w = new QueryWrapper<>();
w.eq("name", "Vue");

字段名是字符串，写错不报错，运行时才炸

LambdaQueryWrapper（推荐）

LambdaQueryWrapper<User> w =
    new LambdaQueryWrapper<>();
w.eq(User::getName, "Vue");

方法引用，编译时检查，重构安全

User::getName 是 Java 8 的方法引用，相当于告诉 MyBatis Plus"用 User 的 name 字段"。MyBatis Plus 通过反射自动推导出数据库列名 name。

常用条件方法

Wrapper 方法 SQL 等价 Prisma 类比
eq(User::getName, "Vue") name = 'Vue' where: { name: "Vue" }
ne(User::getName, "Vue") name != 'Vue' where: { NOT: { name: "Vue" } }
gt(User::getId, 5) id > 5 where: { id: { gt: 5 } }
ge(User::getId, 5) id >= 5 where: { id: { gte: 5 } }
lt(User::getId, 10) id < 10 where: { id: { lt: 10 } }
le(User::getId, 10) id <= 10 where: { id: { lte: 10 } }
like(User::getName, "Vu") name LIKE '%Vu%' where: { name: { contains: "Vu" } }
likeRight(User::getName, "Vu") name LIKE 'Vu%' 前缀匹配（以 Vu 开头）
isNull(User::getEmail) email IS NULL where: { email: null }
orderByDesc(User::getId) ORDER BY id DESC orderBy: { id: 'desc' }

链式调用 -- 多条件组合

Wrapper 方法返回 this，可以链式拼接：

LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
wrapper.like(User::getName, "e")    // name LIKE '%e%'
       .gt(User::getId, 1)          // AND id > 1
       .orderByDesc(User::getId);   // ORDER BY id DESC

List<User> users = userMapper.selectList(wrapper);
// SQL: SELECT id,name,email FROM users
//      WHERE name LIKE '%e%' AND id > 1
//      ORDER BY id DESC

条件判断写法

实际开发中，搜索参数是可选的。Wrapper 每个方法都支持第一个参数为 boolean 条件：

wrapper.like(name != null && !name.isEmpty(),
             User::getName, name)

条件为 false 时该 WHERE 子句不加入 SQL。比写 if 更简洁。

第五步：重构 GET /users -- 搜索 + 分页一体

先往数据库多插几条数据，让分页有意义。在 DBeaver 中执行：

    ('Ember', 'ember@dev.com'),
    ('Knockout', 'knockout@dev.com'),
    ('Aurelia', 'aurelia@dev.com'),
    ('Meteor', 'meteor@dev.com'),
    ('Polymer', 'polymer@dev.com'),

现在有 16 条数据了。把 UserController.java 中的 getAll() 方法替换为分页搜索版：

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;

// ... 其他 import 不变

@GetMapping
public Page<User> getList(
        @RequestParam(defaultValue = "1") long page,
        @RequestParam(defaultValue = "10") long size,
        @RequestParam(required = false) String name,
        @RequestParam(required = false) String email
) {
    // 1. 创建分页对象：第 page 页，每页 size 条
    Page<User> pageObj = new Page<>(page, size);

    // 2. 构建查询条件
    LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
    wrapper.like(name != null && !name.isEmpty(), User::getName, name)
           .like(email != null && !email.isEmpty(), User::getEmail, email)
           .orderByDesc(User::getId);

    // 3. 执行分页查询
    return userMapper.selectPage(pageObj, wrapper);
}
参数 类型 默认值 说明
page long 1 页码，从 1 开始
size long 10 每页条数
name String null（可选） 按姓名模糊搜索
email String null（可选） 按邮箱模糊搜索

@RequestParam 详解

@RequestParam(defaultValue = "1") -- 如果 URL 没传这个参数，用默认值 1。
@RequestParam(required = false) -- 参数可选，不传时值为 null。
这和 Vue3 中 route.query.page ?? 1 的逻辑一模一样。

分页响应结构详解

selectPage 返回的 Page<User> 对象会被 Spring 自动转为 JSON。前端对接时关注这几个字段：

JSON 字段 类型 说明 Vue3 对接
records 数组 当前页的数据列表 v-for="user in res.records"
total 数字 总记录数 <el-pagination :total="res.total">
current 数字 当前页码 v-model:current-page="res.current"
size 数字 每页条数 v-model:page-size="res.size"
pages 数字 总页数 计算翻页按钮显隐

完整 UserController 代码

到目前为止，UserController.java 完整代码如下：

package com.yourname.demo;

import com.baomidou.mybatisplus.core.conditions.query.LambdaQueryWrapper;
import com.baomidou.mybatisplus.extension.plugins.pagination.Page;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.web.bind.annotation.*;
import java.util.List;

@RestController
@RequestMapping("/users")
public class UserController {

    @Autowired
    private UserMapper userMapper;

    // 搜索 + 分页
    @GetMapping
    public Page<User> getList(
            @RequestParam(defaultValue = "1") long page,
            @RequestParam(defaultValue = "10") long size,
            @RequestParam(required = false) String name,
            @RequestParam(required = false) String email
    ) {
        Page<User> pageObj = new Page<>(page, size);
        LambdaQueryWrapper<User> wrapper = new LambdaQueryWrapper<>();
        wrapper.like(name != null && !name.isEmpty(), User::getName, name)
               .like(email != null && !email.isEmpty(), User::getEmail, email)
               .orderByDesc(User::getId);
        return userMapper.selectPage(pageObj, wrapper);
    }

    // 按 ID 查询单条
    @GetMapping("/{id}")
    public User getById(@PathVariable Long id) {
        return userMapper.selectById(id);
    }

    // 创建
    @PostMapping
    public User create(@RequestBody User user) {
        userMapper.insert(user);
        return user;
    }

    // 更新
    @PutMapping("/{id}")
    public User update(@PathVariable Long id, @RequestBody User user) {
        user.setId(id);
        userMapper.updateById(user);
        return userMapper.selectById(id);
    }

    // 删除
    @DeleteMapping("/{id}")
    public String delete(@PathVariable Long id) {
        userMapper.deleteById(id);
        return "Deleted user " + id;
    }
}

小测验

LambdaQueryWrapper 相比 QueryWrapper 的主要优势是什么？

  • 运行速度更快且内存占用更少
  • 字段名编译时检查重构更安全
  • 支持更多种 SQL 操作和子查询
  • 不需要导入任何额外依赖包

小测验

new Page<User>(2, 5) 表示什么含义？

  • 查询第 2 条到第 5 条记录
  • 每页 2 条记录共分 5 页
  • 查询第 2 页每页 5 条记录
  • 总共 2 页每页显示 5 条

小测验

updateById(user) 如何处理 user 对象中的 null 字段？

  • 将数据库对应字段更新为 NULL
  • 跳过不更新该字段的值
  • 抛出空指针异常并报错
  • 自动填充默认值后再更新
