第 11 课：全局异常处理

预计用时：20 分钟 | 难度：中级 | 前置知识：第 10 课 Java 包与项目结构

目标：让错误也返回 JSON

第 9 课的 createUser 里有一段邮箱查重逻辑：重复就抛 IllegalArgumentException。你测试时一定发现了 -- 抛异常后 Spring Boot 返回的是一整页 500 HTML 错误页（Whitelabel Error Page），你的 Vue3 前端 axios 拿到 HTML 而非 JSON，根本没法解析。

这就像前端把原始 Error 对象直接 alert() 给用户看 -- 不专业，也没法用。这节课我们用 @RestControllerAdvice 统一拦截异常，返回规范的 JSON 错误响应。

前端（你已熟悉）

// Express 错误中间件
app.use((err, req, res, next) => {
  res.status(500).json({
    code: 500,
    message: err.message
  })
})

兜底所有未捕获的错误，统一返回 JSON

后端（今天学的）

// Spring Boot 全局异常处理
@RestControllerAdvice
public class GlobalExceptionHandler {

  @ExceptionHandler(IllegalArgumentException.class)
  public Map<String, Object> handle(
      IllegalArgumentException e) {
    return Map.of("code", 400,
      "message", e.getMessage());
  }
}

兜底所有 Controller 抛出的异常

为什么需要全局异常处理？

没有全局处理时，Spring Boot 的默认行为是：

  1. Service 抛出异常，Controller 没有 try-catch
  2. 异常一路冒泡到 Spring MVC
  3. Spring MVC 没有找到处理器 -> 返回 500 状态码 + HTML 错误页
问题 影响
返回 HTML 而非 JSON 前端 res.data 解析出乱码或空
暴露服务器内部信息 堆栈跟踪、类名、行号全给前端看了 -- 安全隐患
状态码全是 500 业务错误（邮箱重复）和系统错误（数据库挂了）无法区分

创建全局异常处理器

新建 common 包和 GlobalExceptionHandler

在 common 包下（com.yourname.demo.common）新建 GlobalExceptionHandler.java：

package com.yourname.demo.common;

import org.springframework.web.bind.annotation.ExceptionHandler;
import org.springframework.web.bind.annotation.RestControllerAdvice;
import java.util.Map;

@RestControllerAdvice   // 全局异常处理，拦截所有 Controller 抛出的异常
public class GlobalExceptionHandler {

    // 拦截业务异常 -- 邮箱重复、参数非法等
    @ExceptionHandler(IllegalArgumentException.class)
    public Map<String, Object> handleIllegalArgument(IllegalArgumentException e) {
        return Map.of("code", 400, "message", e.getMessage());
    }
}

逐行解读：

注解 / 代码 前端类比 含义
@RestControllerAdvice Express app.use((err, req, res, next)) 全局异常处理器，拦截所有 @RestController 抛出的异常
@ExceptionHandler(IllegalArgumentException.class) if (err instanceof TypeError) 指定要捕获的异常类型。只拦这种异常，其他的不拦
public Map<String, Object> handle(...) res.json({ code, message }) 返回值自动转 JSON。和 Controller 方法一样，Map 会被序列化

不支持

Map.of() 是 JDK 9+。JDK 8 替代：

Map<String, Object> error = new HashMap<>();
error.put("code", 400);
error.put("message", e.getMessage());
return error;

测试：邮箱查重现在返回 JSON

重启应用。用已存在的邮箱 POST 创建用户：

POST http://localhost:8080/api/users
Content-Type: application/json

{"name":"Dup","email":"vue@dev.com"}

之前（没有全局处理）：返回 500 + HTML 错误页

现在：返回 JSON：

{
  "code": 400,
  "message": "邮箱已被注册: vue@dev.com"
}

你的 Vue3 前端现在能正常解析错误了：res.data.message 就是错误提示。

加一个兜底处理器

业务异常用 IllegalArgumentException 拦了，但如果数据库挂了、空指针了，还是会返回 HTML。加一个兜底异常处理器：

// 拦截所有其他异常 -- 兜底
@ExceptionHandler(Exception.class)
public Map<String, Object> handleException(Exception e) {
    return Map.of("code", 500, "message", "服务器内部错误");
}

不要把堆栈信息返回给前端

兜底处理器返回固定消息 "服务器内部错误"，不返回 e.getMessage()。因为未预期的异常可能包含敏感信息（SQL 语句、类名、路径等）。详细堆栈应该记到日志里，不是返回给前端。

前端类比：你也不会把 err.stack 直接返回给用户，而是返回"系统繁忙，请稍后重试"。

异常处理优先级

如果有多个 @ExceptionHandler，Spring 按异常类型的精确度匹配：

抛出的异常 匹配的处理器 返回
IllegalArgumentException handleIllegalArgument（精确匹配） {"code":400,"message":"邮箱已被注册"}
NullPointerException handleException（兜底） {"code":500,"message":"服务器内部错误"}
RuntimeException handleException（兜底） {"code":500,"message":"服务器内部错误"}

规则：越具体的异常类型优先匹配。Exception 是所有异常的父类，所以放在最后兜底。

完全兼容

@RestControllerAdvice 和 @ExceptionHandler 都是 Spring MVC 3.2+ 的特性，JDK 8 / Spring Boot 2.x 完全支持。无兼容性问题。

小测验

@RestControllerAdvice 的作用是什么？

  • 标记类为 REST API 控制器
  • 全局捕获异常并返回 JSON
  • 配置 Spring Boot 自动装配
  • 管理数据库连接池配置

小测验

Service 抛出异常，没有全局异常处理时会怎样？

  • 返回 404 Not Found 页面
  • 正常返回空 JSON 响应
  • 返回 500 HTML 错误页面
  • 自动重试该次请求操作

小测验

@ExceptionHandler(IllegalArgumentException.class) 的参数指定了什么？

  • 要返回的 HTTP 状态码
  • 要捕获的异常类型
  • 要调用的 Service 方法
  • 要记录的日志级别
