第 10 课：Java 包与项目结构

预计用时：20 分钟 | 难度：入门 | 前置知识：第 9 课 Service 层

目标：把散落的类整理进包

跟着课程走到这里，你的 com.yourname.demo 包下已经堆了五六个类：

src/main/java/com/yourname/demo/
├── DemoApplication.java       ← 启动类
├── UserController.java        ← 控制器
├── User.java                  ← 实体
├── UserMapper.java            ← 数据访问
├── MybatisPlusConfig.java     ← 配置
├── UserService.java           ← 业务接口（第 9 课）
└── UserServiceImpl.java       ← 业务实现（第 9 课）

项目小的时候这样平铺没问题。但类一多，就和你前端把所有 .vue 文件全扔 src/ 根目录一样 -- 找起来费劲，职责边界模糊。这节课我们给它们分包。

本课不引入新依赖

这节课纯做项目结构重组，不改任何业务代码，不改 pom.xml。重组后项目行为完全不变 -- 这就是重构的本质。

什么是包？

你前端项目里 src/ 下有 components/、stores/、api/、utils/ 等文件夹。Java 的 package（包）就是同一回事：文件夹 + 命名空间。

前端（你已熟悉）

src/
├── components/
│   └── UserCard.vue
├── stores/
│   └── user.ts
├── api/
│   └── user.ts
└── utils/
    └── format.ts

文件夹即模块边界，import 路径对应目录

后端（今天学的）

com/yourname/demo/
├── controller/
│   └── UserController.java
├── service/
│   └── UserService.java
├── mapper/
│   └── UserMapper.java
├── entity/
│   └── User.java
└── config/
    └── MybatisPlusConfig.java

包即目录，package 声明对应目录路径

规则 说明 前端类比
包名 = 目录路径 com.yourname.demo.controller 对应 com/yourname/demo/controller/ 目录 ./src/components 对应 src/components/ 文件夹
package 声明必须在文件第一行 每个 .java 文件开头必须声明自己属于哪个包（除入口外） 不需要 -- JS/TS 没有这个要求
跨包引用要 import 用其他包的类必须 import com.yourname.demo.entity.User; import UserCard from './components/UserCard.vue'
同包内不用 import 同一个包里的类互相使用，不需要 import 同文件夹下的文件可以省略路径

标准 Spring Boot 包结构

Java 后端社区有一套约定俗成的分包方式，几乎所有 Spring Boot 项目都遵循：

包名 放什么 前端类比
controller @RestController 类 -- 处理 HTTP 请求 pages/ 或 views/ -- 页面/路由组件
service @Service 类 -- 业务逻辑 stores/ 或 composables/ -- 业务状态与逻辑
mapper BaseMapper 接口 -- 数据库访问 api/ -- axios 请求封装
entity @TableName 类 -- 数据库表映射 types/ 或 models/ -- TypeScript 类型定义
config @Configuration 类 -- 框架配置 plugins/ 或 middleware/ -- 框架级配置
根包 DemoApplication -- 启动类，放在根包 main.ts -- 入口文件放 src/ 根目录

为什么启动类放根包？

@SpringBootApplication 内含 @ComponentScan，默认从启动类所在的包开始扫描，包括所有子包。启动类放在根包 com.yourname.demo，Spring 就能自动发现 controller/、service/、config/ 等子包里的所有组件。如果把启动类放深了，外面的类就扫不到。

把类移动到包中

IDEA 提供了自动重构功能 -- 移动类时会自动更新 package 声明和所有引用处的 import。你不需要手动改任何文件。

方法一：拖拽（最简单）

在项目面板中，直接把 User.java 拖到 entity 包上。IDEA 会弹出确认框：

Move class 'User' to package 'com.yourname.demo.entity'? ✓ Search for references ← 确保勾选，自动更新所有 import [Refactor] [Cancel]

点击 Refactor。IDEA 会：

  • 把文件物理移动到 entity/ 目录
  • 把文件内的 package com.yourname.demo; 改成 package com.yourname.demo.entity;
  • 在所有引用 User 的文件中自动添加 import com.yourname.demo.entity.User;

方法二：Move 重构（快捷键 F6）

选中 UserMapper.java，按 F6（或右键 -> Refactor -> Move）：

Move Members to Package To package: com.yourname.demo.mapper ✓ Search for references

点击 Refactor，效果与拖拽相同。

逐个移动所有类

按下面的对应关系，把每个类移到对应的包：

类 移到
UserController controller
User entity
UserMapper mapper
MybatisPlusConfig config
UserService + UserServiceImpl service
DemoApplication 不动 -- 留在根包

移动后的结构

src/main/java/com/yourname/demo/
├── DemoApplication.java           ← 根包（启动类）
├── controller/
│   └── UserController.java
├── entity/
│   └── User.java
├── mapper/
│   └── UserMapper.java
├── config/
│   └── MybatisPlusConfig.java
└── service/
    ├── UserService.java
    └── UserServiceImpl.java

干净清爽 -- 一眼就知道每个类干什么，和前端项目的 src/ 结构一样清晰。

package 声明与 import 的变化

移动之后，每个类的 package 声明变了，跨包引用需要加 import。IDEA 已经帮你自动改好了，但你需要理解原理。

以 UserController 为例，移动前：

package com.yourname.demo;          ← 所有类都在同一个包

import org.springframework.web.bind.annotation.*;
// 不需要 import User -- 同包内直接用

@RestController
public class UserController {
    private UserMapper userMapper;  ← 同包，不用 import

移动后：

package com.yourname.demo.controller;  ← 包名变了

import com.yourname.demo.entity.User;       ← 跨包，要 import
import com.yourname.demo.mapper.UserMapper;  ← 跨包，要 import
import com.yourname.demo.service.UserService;← 跨包，要 import
import org.springframework.web.bind.annotation.*;

@RestController
public class UserController {
    private UserService userService;  ← 用 import 引入的类型

关键规则

package 声明必须与目录路径完全一致。如果 UserController.java 在 controller/ 目录下，但文件内写的是 package com.yourname.demo;，Java 编译器直接报错。

这是 Java 和前端的一个显著区别 -- JS/TS 文件放哪个目录不影响其内容，但 Java 文件的 package 声明必须和目录严格对应。

@MapperScan 与子包扫描

第 6 课在 DemoApplication 上加了 @MapperScan("com.yourname.demo")。现在 UserMapper 搬到了 com.yourname.demo.mapper 子包，@MapperScan 要改吗？

不用改。 @MapperScan 扫描的是指定包及其所有子包，就像前端 import.meta.glob('./src/**/*.vue') 递归匹配子目录一样：

写法 扫描范围 能否找到 UserMapper
@MapperScan("com.yourname.demo") 根包 + 所有子包 能 -- mapper 是子包
@MapperScan("com.yourname.demo.mapper") 仅 mapper 包 能 -- 精确指定
@MapperScan("com.yourname.demo.controller") 仅 controller 包 不能 -- Mapper 不在这

同理：@ComponentScan 也是递归的

@SpringBootApplication 内含的 @ComponentScan 从启动类所在包开始递归扫描。所以 @RestController、@Service、@Configuration 等注解标记的类，无论放在哪个子包，Spring 都能自动发现。这就是启动类必须放根包的原因。

如果你把 @MapperScan 从 DemoApplication 搬到了 MybatisPlusConfig（两者效果相同），也不需要改扫描路径 -- @MapperScan 的扫描与它写在哪个类上无关，只看路径参数。

验证：重组后一切照常

运行项目

按 Shift + F10 运行 DemoApplication。如果 IDEA 的重构正确执行了，项目应该零报错启动。

如果报错

常见问题：Cannot find symbol User 或 Cannot find symbol UserMapper。说明移动时 IDEA 没有自动更新 import。手动在报错的文件顶部加上对应的 import com.yourname.demo.entity.User; 即可。按 Alt + Enter 让 IDEA 自动修复。

测试所有接口

用浏览器或 IDEA HTTP Client 测试，行为应该和重组前完全一致：

  • GET /users?page=1&size=5 -- 分页列表正常
  • POST /users -- 创建用户正常
  • DELETE /users/1 -- 删除正常

重构的定义：不改变外部行为，只调整内部结构。

完全兼容

Java 包机制是 JDK 1.0 就有的基础特性，与 JDK 版本无关。本课所有内容在 JDK 8 下完全相同。

以后新建类时

分包之后，新建类时要注意选对包。在 IDEA 中：

  1. 右键目标包（如 controller）-> New -> Java Class
  2. 输入类名，IDEA 自动生成正确的 package 声明

如果右键的是 com.yourname.demo 根包新建类，package 声明就是 com.yourname.demo；如果右键的是 controller 子包，声明就是 com.yourname.demo.controller。IDEA 根据你右键的位置自动生成，不需要手写。

Alt + Enter 自动补 import

在代码中使用其他包的类时（比如在 Controller 里用 User），如果没 import，类名会标红。按 Alt + Enter -> Import Class，IDEA 自动添加正确的 import 语句。详见 IDEA 快捷键速查表。

小测验

Java 的 package 声明必须与什么保持一致？

  • 类名必须与文件名相同
  • 包名必须与目录路径一致
  • 包名必须与项目名相同
  • 类名必须与包名相同

小测验

@MapperScan("com.yourname.demo") 能扫描到子包中的 Mapper 吗？

  • 不能只扫描当前包的类
  • 能扫描当前包及所有子包
  • 不能需要单独配置子包
  • 不能子包需要额外注解

小测验

DemoApplication 启动类应该放在哪个位置？

  • 放在 controller 子包里面
  • 放在最深层的子包里面
  • 放在根包扫描所有子包
  • 放在项目 pom.xml 的同级
